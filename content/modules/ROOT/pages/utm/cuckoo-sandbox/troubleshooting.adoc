= Поиск и устранение неисправностей Cuckoo Sandbox

Разделы до xref:utm/cuckoo-sandbox/troubleshooting.adoc#kvm-troubleshooting[устранения неисправностей KVM] относятся к стенду на **VirtualBox** (`192.168.56.0/24`, InetSim на host-only). Для **KVM/libvirt** (`virbr0`, `192.168.122.0/24`) — сразу к разделу KVM ниже.

Внимание: Ошибки виртуальной сети! Виртуальная сеть — жизненно важный компонент для Cuckoo, вы должны быть абсолютно уверены, чтобы обеспечить связь между хостом и гостевой системой. Большинство проблем, о которых сообщают пользователи, связаны с неправильной настройкой их сети. Если вы не уверены в этом, проверьте документацию к вашему программному обеспечению для виртуализации и проверьте связь с помощью ping и telnet.

== Гостевая Windows 10 и язык образа

В этом руководстве гостевая система — Windows 10 x64. Установочный образ и окружение Windows должны быть с английской локализацией (язык дистрибутива, не только переключатель языка в уже установленной ОС): иначе Cuckoo Sandbox часто ведёт себя нестабильно. Если симптомы непонятны, сначала сверьтесь с xref:utm/cuckoo-sandbox/installationVBox.adoc#guest-vm-os[установкой VirtualBox] (образ и гостевая ВМ) или xref:utm/cuckoo-sandbox/installationKVM.adoc#win10-setup[установкой KVM] (этап установки Windows).

== Связность и InetSim

Если дваусторонний ping между хостом и гостем не выполняется:

* проверьте `service_bind_address` и `dns_default_ip` в `/etc/inetsim/inetsim.conf` (совпадают с адресом Host-only, например `192.168.56.1`);
* выполните `sudo systemctl status inetsim` при необходимости `sudo systemctl restart inetsim`;
* повторите настройку адаптера по разделу xref:utm/cuckoo-sandbox/installationVBox.adoc#guest-network[настройке гостевой сети VirtualBox] (для KVM — сеть `virbr0` в xref:utm/cuckoo-sandbox/installationKVM.adoc[установке KVM]).

== Something went wrong в веб-интерфейсе

Если после *Analyze* отображается ошибка Something went wrong, загляните в терминал с `cuckoo -d`: если задача там стартовала, это может быть сбой веб-слоя, а не основного процесса.

== Логи и Tesseract

Сообщения в логе могут отличаться между установками. В руководстве указано, что ошибочное включение Tesseract без OCR даёт красные записи — при необходимости отключите `tesseract` в `processing.conf`.

== Выбор InetSim в Network Routing

Маршрутизация должна быть INETSIM. Если недоступна — см. xref:utm/cuckoo-sandbox/configuration.adoc[варианты конфигурации] и файл `routing.conf`.

Первый успешный анализ можно проверять по выполненному отчёту по тестовому `eicar.zip`; возможны ошибки, требующие ручной доработки конкретного стенда.

[[pcap-group]]
== usermod: group 'pcap' does not exist

*Симптом:* при `usermod -a -G libvirt,kvm,pcap cuckoo` — `group 'pcap' does not exist`.

*Причина:* группа `pcap` создаётся позже (`groupadd`), после установки tcpdump.

*Решение:* сначала только `libvirt,kvm`; затем блок tcpdump:

[source,shell]
----
sudo groupadd pcap 2>/dev/null || true
sudo usermod -a -G pcap cuckoo
sudo chgrp pcap /usr/sbin/tcpdump
sudo setcap cap_net_raw,cap_net_admin=eip /usr/sbin/tcpdump
----

После любого `usermod` — log out / log in или `sudo su - cuckoo`.

[[postgresql-heredoc-backslash]]
== psql heredoc: invalid command \

*Симптом:* при `sudo -u postgres psql <<'EOF'` между `CREATE ROLE` и `CREATE DATABASE` — `invalid command \`.

*Причина:* в heredoc с кавычками (`<<'EOF'`) символ `\` в конце строки **не** склеивает SQL, а передаётся в `psql` как отдельная meta-команда.

*Решение:* `CREATE DATABASE` **одной строкой**, без `\`:

[source,shell]
----
sudo -u postgres psql <<'EOF'
CREATE USER cuckoo WITH PASSWORD 'ваш_пароль';
CREATE DATABASE cuckoo ENCODING 'UTF8' LC_COLLATE='en_US.UTF-8' LC_CTYPE='en_US.UTF-8' TEMPLATE template0 OWNER cuckoo;
GRANT ALL PRIVILEGES ON DATABASE cuckoo TO cuckoo;
\q
EOF
----

Если при ошибке уже видели `CREATE ROLE`, `CREATE DATABASE`, `GRANT` — БД, скорее всего, **создана**. Проверка:

[source,shell]
----
psql -h localhost -U cuckoo -d cuckoo -c 'SELECT version();'
sudo -u postgres psql -c "\l" | grep cuckoo
----

Повторный `CREATE USER` / `CREATE DATABASE` без `IF NOT EXISTS` даст «already exists» — это нормально, идите дальше по документу.

[[resultserver-bind]]
== Cuckoo: Cannot assign requested address (192.168.56.1:2042)

*Симптом:* после добавления только `connection` в `cuckoo.conf` команда `cuckoo` падает:
`Unable to bind ResultServer on 192.168.56.1:2042 [Errno 99] Cannot assign requested address`.

*Причина:* после `cuckoo init` остаются дефолты **VirtualBox** (`192.168.56.1`). На KVM нужен **`192.168.122.1`** (virbr0). Guest Windows на этом шаге **не обязателен**.

*Решение:* в `~/.cuckoo/conf/cuckoo.conf`:

[source,ini]
----
[cuckoo]
machinery = kvm

[resultserver]
ip = 192.168.122.1
port = 2042

[database]
connection = postgresql://cuckoo:ПАРОЛЬ@localhost/cuckoo
----

[source,shell]
----
ip addr show virbr0 | grep 192.168.122.1
source ~/venv/bin/activate
cuckoo
----

403 на `updates.json` — не критично. Полная настройка — xref:utm/cuckoo-sandbox/installationKVM.adoc[установка KVM], раздел PostgreSQL / конфигурация.

[[defender-error-225]]
== Error 225 (Windows Defender)

*Симптом:* в Cuckoo Log: `WindowsError: [Error 225] … file contains a virus or potentially unwanted software`; behavior log пустой.

*Решение:* полное отключение Defender в guest — xref:utm/cuckoo-sandbox/installationKVM.adoc#win10-defender-off[установка KVM: реестр + Safe Mode] → перезагрузка → **новый** снапшот `clean`:

----

[[guest-ping-host-fail]]
== Ping: с guest `.1` OK, с host guest — 100% loss

*Симптом:* в guest `ping 192.168.122.1` — OK; на host `ping 192.168.122.105` — **100% packet loss**.

*Когда бывает:* чаще всего **до** отключения брандмауэра (этап 6 xref:utm/cuckoo-sandbox/installationKVM.adoc[установки KVM]) или если ping с host делали раньше времени. После перезагрузки guest с выключенным firewall ping с host должен проходить.

image::utm/cuckoo-sandbox/kvm/W10-19-ping-host-fail-firewall.png[guest OK, host fail]

*Решение (lab):* в guest отключить firewall — xref:utm/cuckoo-sandbox/installationKVM.adoc#win10-firewall[этап 6 в установке KVM].

*Решение (точечно):* **wf.msc** → Inbound Rules → **File and Printer Sharing (Echo Request - ICMPv4-In)** → **Enable** (профиль Private).

*Проверка:* с host `ping -c 3 192.168.122.105` → 0% loss. Для Cuckoo важнее `nc -zv 192.168.122.105 8000` после установки Agent.

[[human-action-center]]
== human=0 и Action Center

Модуль `human` кликает по подстроке **new** в «No **new** notifications». Отключение Action Center в guest — этап 9 в xref:utm/cuckoo-sandbox/installationKVM.adoc[установке KVM].

**Submit с human=0 (host)** — для **notepad**, **mspaint** и других GUI-сэмплов (**→ `cuckoo`, venv**):

[source,shell]
----
cuckoo submit --options human=0 /tmp/notepad.exe
cuckoo submit --options human=0 /tmp/mspaint.exe
----

В Web → Analyzer log: **нет** повторов `Action Center … clicking it`; на скриншотах — окно сэмпла, а не трей.

[[firefox-guest]]
== Firefox в guest (не ставить в базовую установку)

В xref:utm/cuckoo-sandbox/installationKVM.adoc[установке KVM] Firefox **не** входит в эталонный guest. На Win10 LTSC в lab он часто **нестабилен** (падения, конфликты с Python 2.7 / старыми зависимостями) и для Cuckoo **не нужен**.

**URL-анализ** — пакет **`ie`** (Internet Explorer встроен в Windows):

[source,shell]
----
cuckoo submit --package ie \
  --options "human=0,route=inetsim,enforce_timeout=yes,free=yes" \
  http://example.com
----

Если Firefox уже установлен и мешает — удалите из guest или не включайте в снапшот `clean`. Для скачивания `agent.py` с host достаточно **Edge** (закрыть промо на этапе 4 установки).
