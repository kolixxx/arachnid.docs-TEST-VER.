= Конфигурация и сценарии настройки CuckooMX

Ниже — пошаговая установка в духе рабочей инструкции (Postfix на Linux, доступ из интернета через OPNsense, Cuckoo по API). Файлы скрипта и примера конфигурации берите из https://gitlab.arachnd.ru/solutions/arachnid.utm/-/tree/main/cuckooMX/cuckooMX%20modified[cuckooMX modified] в репозитории Arachnid.UTM. Команды выполняйте от пользователя с правами `sudo`, где это указано — от `root`.

== Установка Postfix и базовых пакетов

Установите Postfix и сопутствующие пакеты (имена пакетов зависят от дистрибутива; для Debian/Ubuntu):

* `postfix` — MTA;
* `postfix-pcre` — поддержка PCRE в конфигурации Postfix (часто нужна для правил);
* `mailutils` — утилиты для проверки почты с консоли.

Во время установки Postfix откроется диалог:

* *Internet Site* — полноценный приём почты в сети (типичный вариант для CuckooMX).
* *Local only* — только локальная машина (для сценария «только localhost» обычно не подходит).

Укажите домен почты (FQDN зоны, в которой будут адреса получателей, например `cuckoo.example.com`). Проверьте, что Postfix запущен и слушает TCP/25:

[source,shell]
----
sudo systemctl status postfix
sudo ss -lntp | grep ':25'
----

== Настройка `main.cf`

Отредактируйте `/etc/postfix/main.cf` (пути и значения замените на свои):

* `myhostname` — имя узла Postfix в почтовой топологии (например `postfix.example.com`).
* `inet_protocols` — при необходимости ограничьте до `ipv4`, если в сети нет маршрутизации IPv6.
* `mynetworks` — добавьте доверенные подсети (например сегмент DMZ: `..., 10.0.3.0/24`).
* `inet_interfaces` — для приёма из сети задайте `all` или явный список интерфейсов вместо `loopback-only`.

Проверка синтаксиса и только *изменённых* параметров:

[source,shell]
----
sudo postfix check
postconf -n
----

Перезапустите Postfix после правок `main.cf`.

== Публикация SMTP через OPNsense (пример)

Если перед Postfix стоит OPNsense:

. На интерфейсе WAN (или нескольких) создайте правило *Firewall* — направление *In*, протокол *TCP*, порт SMTP (25), источник по политике, назначение — адрес Postfix в DMZ.
. Настройте *NAT → Port Forward*: внешний интерфейс, внешний адрес/порт 25, перенаправление на внутренний IP Postfix (`Redirect target IP`). При необходимости используйте *one-to-one NAT* и корректный ARP/прокси в вашей топологии.

Проверьте доставку тестового письма с внешней машины (например с тестового клиента в другой подсети).

== Извлечение вложений из тестового ящика

Postfix передаёт в фильтр MIME-тело, а не «голый файл». Для ручной проверки вложений из файла ящика удобно использовать `ripmime`:

[source,shell]
----
sudo apt install ripmime
ripmime -i /path/to/mailbox -d /path/to/extract/dir
----

Здесь `-i` — файл ящика/Maildir, `-d` — каталог для извлечённых частей.

== Установка CuckooMX

=== Зависимости Perl и утилиты

Установите модули Perl, которые требует `cuckoomx.pl` из вашей поставки (список смотрите в начале скрипта или в README каталога; типично: `MIME::Parser`, `Digest::MD5`, `File::LibMagic`, клиент HTTP для API — в зависимости от версии скрипта). Также установите `ripmime`, если используете его для отладки MIME.

=== Размещение файлов

Создайте каталоги конфигурации и скрипта, например:

[source,shell]
----
sudo mkdir -p /data/cuckoo/conf
----

Скопируйте из репозитория:

* `cuckoomx.conf` → `/data/cuckoo/conf/cuckoomx.conf`;
* `cuckoomx.pl` → `/data/cuckoo/cuckoomx.pl`.

Сделайте скрипт исполняемым:

[source,shell]
----
sudo chmod +x /data/cuckoo/cuckoomx.pl
----

Права на каталоги и файлы настройте по политике безопасности: пользователю, от которого запускается pipe, нужны чтение конфигурации, запись в рабочий/карантинный каталог (`outputdir` в XML) и возможность вызвать `sendmail`. Избегайте избыточных `chmod 777` на продакшене; в черновых лабораторных инструкциях они встречаются для отладки, но для боя лучше сузить ACL.

=== Редактирование `cuckoomx.conf`

Откройте `/data/cuckoo/conf/cuckoomx.conf` и задайте:

* В элементе `api-url` — базовый URL REST API Cuckoo, например `http://192.168.x.x:8090` (для HTTPS убедитесь, что Perl-стек доверяет сертификату или используйте корпоративный CA).
* В `api-token` — токен из конфигурации Cuckoo на стороне песочницы; вводите символы внимательно (путаница латинской «O» и нуля «0» даёт отказ авторизации).
* В `guest` — имя гостевой ВМ в Cuckoo, на которой выполняется анализ (как в веб-интерфейсе/конфиге песочницы).

Остальные параметры (игнорируемые MIME, ZIP, пути `sendmail`, facility syslog) настройте по необходимости.

Проверка API с узла Postfix (подставьте свой URL и токен):

[source,shell]
----
curl -H "Authorization: Bearer ВАШ_ТОКЕН" http://192.168.x.x:8090/tasks/list/1
----

(точный путь и заголовок зависят от версии API Cuckoo в вашей установке — сверяйтесь с xref:utm/cuckoo-sandbox/reference.adoc[документацией Cuckoo Sandbox] в этом сайте и с вашим `cuckoo.conf`.)

== Интеграция с Postfix: `master.cf`

[source,shell]
----
cd /etc/postfix
sudo nano master.cf
----

. В строке сервиса `smtp` … `smtpd` добавьте опцию `content_filter` *на той же строке*, что и `smtpd`, через пробел (как в примере ниже). Если вынести `-o content_filter=…` отдельной строкой без привязки к сервису, `postfix check` часто сообщает об ошибке в `master.cf`.

+
[source]
----
smtp      inet  n       -       y       -       -       smtpd
  -o content_filter=cuckoomx
----
+
(Отступ второй строки — как в вашем шаблоне `master.cf`; важно, чтобы продолжение относилось к сервису `smtp`.)

. В конец файла добавьте новый сервис `cuckoomx` типа `pipe`, по образцу upstream: вторая строка с `user=` и `argv=` на ваш путь к `cuckoomx.pl`. Пользователь не должен быть `root`; у него должны быть доступы к конфигу, `outputdir` и `sendmail`.

Перезагрузка конфигурации Postfix:

[source,shell]
----
sudo systemctl reload postfix
----

== Проверка после установки

. Отправьте письмо с вложением на адрес на вашем Postfix.
. Убедитесь, что в каталоге карантина/рабочих файлов (например под `/data/cuckoo/`) появляются подкаталоги обработки, а в Cuckoo — новые задачи.
. Смотрите журнал:

+
[source,shell]
----
sudo tail -f /var/log/mail.log | grep cuckoomx
----
